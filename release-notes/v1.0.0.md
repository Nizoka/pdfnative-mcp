# pdfnative-mcp v1.0.0 — First stable release

**Tag:** `v1.0.0`
**Release date:** 2026-01-15
**Built on:** [pdfnative v1.2.0](https://github.com/Nizoka/pdfnative/releases/tag/v1.2.0)

## Highlights

This is the **first stable release** of `pdfnative-mcp`. It consolidates the deferred v0.4 → v1.0 roadmap into a single major release and commits to API stability via the new per-tool `_meta.apiVersion` field.

- 🆕 **Three new tools:** `verify_pdf` (PAdES signature verification), `add_attachment` (Factur-X / ZUGFeRD PDF/A-3 invoices), `extract_text` (best-effort plain-text extraction).
- 🆕 **Smart-table fields** on `add_table`: `wrap`, `repeatHeader`, `zebra`, `caption`, `minRowHeight`, `cellPadding`.
- 🆕 **Signing ergonomics:** `sign_pdf` accepts ECDSA PKCS#8 DER keys and auto-injects a placeholder when missing.
- 🆕 **`inspect_pdf` parity:** new `hasSignaturePlaceholder` and `attachments[]` fields, two new `check` enum values (`placeholder`, `attachments`).
- 🆕 **Opt-in content-addressed cache** (`PDFNATIVE_MCP_CACHE_DIR`) — SHA-256 keyed, 1 h TTL, 256 MiB LRU.
- 🆕 **MCP `_meta.apiVersion`** + per-tool **`_meta.examples`** for AI-agent discovery.
- 🆕 **PDF/A authoring guide:** [`docs/guides/PDFA.md`](../docs/guides/PDFA.md).
- 🆕 **Registry-ready:** `mcpName`, top-level `server.json`, `llms.txt`, 70+ npm keywords.
- 🛠 **Env-var rename:** `PDFNATIVE_MCP_OUTPUT_DIR` (canonical; old `PDFNATIVE_MPC_OUTPUT_DIR` deprecated with a one-shot warning).
- ⏭ **Deferred to v1.1:** `merge_pdfs`, `split_pdf`, `redact_pdf` — require pdfnative page-tree primitives not yet exported.

## Added

- `verify_pdf` tool — per-signature `{ valid, integrity, signerSubject, signingTime, reason, chainTrust, errors[] }`. Supports RSA-SHA256 and ECDSA-SHA256 (P-256). Optional `trustedRootsDerBase64` enables full chain verification.
- `add_attachment` tool — PDF/A-3 generator with one or more embedded files. Each attachment ≤ 8 MiB; primary use case: Factur-X / ZUGFeRD invoices.
- `extract_text` tool — content-stream text extraction (Tj / ' / " / TJ operators, literal + hex strings). Encrypted PDFs rejected with `EXTRACTION_UNSUPPORTED`. Reports `extractable: false` when subset fonts without `/ToUnicode` yield no text.
- `add_table` smart-table fields (pdfnative v1.2): `wrap`, `repeatHeader`, `zebra`, `caption`, `minRowHeight`, `cellPadding`.
- `sign_pdf`: ECDSA PKCS#8 DER private key support (`ecPrivateKeyDerBase64`); `autoInjectPlaceholder` (default `true`).
- `inspect_pdf`: `hasSignaturePlaceholder` (true when any `/Sig` widget has empty `/Contents`); `attachments[]` summary (name, mimeType, size, relationship, description); new `check` values `placeholder`, `attachments`.
- Opt-in content-addressed cache (`src/cache.ts`): enabled via `PDFNATIVE_MCP_CACHE_DIR`; SHA-256 over canonical JSON; 1 h TTL; 256 MiB LRU.
- MCP `_meta.apiVersion = '1.0.0'` on every tool, plus per-tool `_meta.examples`.
- Documentation: `docs/guides/PDFA.md`.
- Examples: `examples/financial-report.json`, `examples/factur-x-invoice.json`, `examples/multilingual-doc.json`, `examples/sign-and-verify.json`.
- Registry artefacts: `mcpName: "io.github.nizoka/pdfnative-mcp"` in `package.json`, top-level `server.json` (MCP registry manifest), top-level `llms.txt`.
- `CITATION.cff`, `.github/FUNDING.yml`.
- README badges: OpenSSF Scorecard, CodeQL.

## Changed

- Dependency `pdfnative`: `^1.1.0` → `^1.2.0`. Pulls in the fix for [pdfnative#45](https://github.com/Nizoka/pdfnative/issues/45) (X.509 SubjectPublicKeyInfo unwrapping for raw cert slicing) and [pdfnative#46](https://github.com/Nizoka/pdfnative/issues/46) (`addSignaturePlaceholder` helper) used by `sign_pdf` and `prepare_signature_placeholder`.
- `prepare_signature_placeholder` now delegates to pdfnative's `addSignaturePlaceholder()` (idempotent against an already-placeholder'd PDF).
- `inspect_pdf` `signed` check semantic: now `signatureCount > 0 && !hasSignaturePlaceholder`. Use the new `placeholder` check for unsigned-placeholder detection.
- Tool count: 12 (was 9 in v0.3.0).

## Fixed

- Env-var typo: `PDFNATIVE_MPC_OUTPUT_DIR` → `PDFNATIVE_MCP_OUTPUT_DIR`. Old name kept as a deprecated alias with a one-shot stderr warning; scheduled for removal in v2.0.0.

## Deferred to v1.1

- `merge_pdfs`, `split_pdf`, `redact_pdf` — pdfnative v1.2 does not yet export page-tree manipulation primitives.
- Per-tool HTTP page-by-page streaming — MCP `structuredContent` requires full bytes; `StreamableHTTPServerTransport` already chunks the response.
- Encrypted-PDF round-trip fixtures — would require implementing the PDF Standard Security Handler in pdfnative.

## Upgrade guide

1. Bump `pdfnative-mcp` to `^1.0.0`.
2. Rename `PDFNATIVE_MPC_OUTPUT_DIR` → `PDFNATIVE_MCP_OUTPUT_DIR` in your MCP client configuration.
3. If you assert `checks.signed === true` against an unsigned placeholder, switch to `check: ['placeholder']`.
4. Add a `verify_pdf` step after `sign_pdf` to validate signatures end-to-end (see [`examples/sign-and-verify.json`](../examples/sign-and-verify.json)).
5. For Factur-X / ZUGFeRD invoices, use `add_attachment` (auto-emits PDF/A-3b).
