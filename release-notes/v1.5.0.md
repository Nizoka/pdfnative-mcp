# pdfnative-mcp v1.5.0

<!-- GitHub Release title: v1.5.0 - charts, forms, encryption round-trip, MCP resources, pdfnative 1.6 -->

_Released 2026-07-21_

v1.5.0 aligns the server with [pdfnative v1.6.0](https://github.com/Nizoka/pdfnative)
and grows the catalogue to **24 tools**. It adds native vector charts, AcroForm
fill/flatten, an encryption round-trip (decrypt + AES-128/256 re-encrypt), rewrites
`extract_text` onto real Unicode extraction with positioned runs, threads a
`password` input through the read-only and page-tree tools, and exposes generated
PDFs as native **MCP resources**. No breaking changes — every existing tool call
returns responses identical to v1.4.0; all new behaviour is opt-in.

## Highlights

- **Native vector charts** — new `add_chart` tool (and a `chart` block in `generate_basic_pdf`): bar / horizontal-bar / line / pie / donut as pure PDF path operators, PDF/A-safe with auto alt text.
- **Fill & flatten forms** — new `read_form_fields` and `fill_form` tools operate on *existing* AcroForms (the counterpart to `add_form`).
- **Encryption round-trip** — new `encrypt_pdf` / `decrypt_pdf`, a `password` input on the read-only tools, and `password` + `encrypt` on `merge_pdfs` / `split_pdf` / `extract_pages`.
- **Real text extraction** — `extract_text` now resolves `/ToUnicode` (no more glyph-index output) and can return positioned runs.
- **MCP resources** — sandboxed generated PDFs are exposed as `pdfnative://output/…` resources with `resources/list` + `resources/read`, plus `resource_link` in file-mode results.
- **Tool annotations** — every tool advertises `readOnlyHint` / `idempotentHint` / `openWorldHint`.

## Added

- **feat(tool): add_chart** — native `ChartBlock` charts (bar/barH/line/pie/donut), multi-series, legends, nice axis ticks, gridlines, hex palettes, tagged `/Figure` + `/Alt`.
- **feat(tool): read_form_fields** — read-only enumeration of an AcroForm's field tree.
- **feat(tool): fill_form** — fill/flatten an existing AcroForm; typed `FORM_FIELD_NOT_FOUND` / `FORM_VALUE_TYPE_ERROR` / `FORM_UNSUPPORTED`.
- **feat(tool): encrypt_pdf** — re-secure with AES-128/256 (owner/user passwords, permissions, password rotation).
- **feat(tool): decrypt_pdf** — emit an unencrypted copy of an RC4 / AES-128 / AES-256 document.
- **feat(read): password** — `inspect_pdf`, `verify_pdf`, `extract_text`, `extract_attachments` accept `password`; `inspect_pdf` gains `encryptionInfo`.
- **feat(pagetree): encrypted round-trip** — `password` + `encrypt` on `merge_pdfs` / `split_pdf` / `extract_pages`.
- **feat(mcp): resources** — generated PDFs as `pdfnative://output/…` resource URIs + `resource_link`.
- **feat(mcp): tool annotations** on all 24 tools.

## Changed

- **chore(deps): pdfnative** `^1.5.0` → `^1.6.0` (additive). Free wins: colour-emoji 221 → 1167 glyphs, spec-compliant AES-256 (R6) hashing, all-string encryption, arrows → math font, tolerant xref reader.
- **chore(api):** `_meta.apiVersion` `1.4.0` → `1.5.0`; package/server versions → `1.5.0`.
- **feat(text): extract_text** rewritten onto pdfnative `extractText()` (real Unicode, optional `includeRuns`, `password`, `maxTextLength`). Output schema unchanged.

## Fixed

- **fix(text):** subset fonts with a `/ToUnicode` CMap now decode to characters, not glyph indices (the documented best-effort limitation is resolved).

## Deferred by design

- **redact_pdf** stays deferred (overlay/flatten ≠ content removal). `verify_pdf` keeps its local P-256 ECDSA verifier (`ecdsaVerifyHash` still not exported by pdfnative 1.6.0). Per-tool HTTP page streaming remains blocked on MCP partial `structuredContent`.

## Install

npm install pdfnative-mcp@1.5.0

## Upgrade

No breaking changes. Drop-in replacement for v1.4.0. Encrypted sources that previously
failed `merge_pdfs` / `split_pdf` / `extract_pages` with `ENCRYPTED_SOURCE` now either
process transparently (empty user password) or return `PASSWORD_REQUIRED` — supply a
`password` to process them.
