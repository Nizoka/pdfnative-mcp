# pdfnative-mcp v1.2.0 — token-frugal responses + registry publish fix

<!-- GitHub Release title: v1.2.0 - token-frugal responses + registry publish fix -->

_Released 2026-06-23_

A minor, backward-compatible release that adds a 14th tool (`extract_attachments`),
text watermarks and opt-in Unicode normalization, makes the read-only tools markedly
more token-efficient for AI agents (typically ~90% fewer output tokens on large
results), upgrades to zod 4, and fixes the MCP registry publish block caused by
`mcpName` casing. No breaking changes: default tool calls return responses identical
to v1.1.0 — all new behaviour is opt-in. The one ergonomic change is that generated
PDFs are now delivered once as an embedded `resource` block instead of being
duplicated into `structuredContent`.

## Highlights

- 🆕 **`extract_attachments` (14th tool)** — read embedded files back out of a PDF, byte-for-byte, completing the Factur-X / ZUGFeRD round-trip with `add_attachment`. Supports a `filename` filter and an `includeData: false` metadata-only probe.
- 💧 **Watermarks** — `generate_basic_pdf` and `add_table` accept an optional `watermark` (text, opacity, angle, colour, position) rendered on every page.
- 🌐 **Unicode `normalize`** — opt-in `NFC`/`NFD`/`NFKC`/`NFKD` on `generate_basic_pdf` and `add_international_text`.
- 🪙 **Token-frugal reads** — `inspect_pdf`, `verify_pdf`, `validate_pdf`, `extract_text`, and `extract_attachments` accept `verbosity: 'summary'` (compact scalar-only verdict) and `fields: ['a','b.c']` (dot-path projection). Composable; defaults unchanged.
- 🔧 **MCP registry publish fix** — `mcpName` now uses the canonical GitHub login casing `io.github.Nizoka/pdfnative-mcp`, matching the registry's case-sensitive validation. The npm package name stays lowercase `pdfnative-mcp`.
- 🪶 **No base64 duplication** — base64-mode PDFs are returned once as an embedded `resource` content block; `structuredContent` carries only `{ mode, sizeBytes }`.
- ⬆ **zod 4** — runtime validation upgraded from zod 3 to zod 4 (SDK peer range already permits it).
- 🤖 **AGENTS.md** — new root agent operations manual (tool catalogue, decision tree, recipes, error table).

## Added

- **feat(tools):** **`extract_attachments`** — read-only extraction of embedded files. Returns `{ attachmentCount, attachments: [{ name, sizeBytes?, mimeType?, relationship?, description?, dataBase64? }] }`. Shares the `collectEmbeddedFiles()` collector with `inspect_pdf` (consistent metadata); rejects encrypted PDFs (`EXTRACTION_UNSUPPORTED`); caps payloads at 16 MiB/file and 32 MiB aggregate (`OUTPUT_TOO_LARGE`); `ATTACHMENT_NOT_FOUND` when a `filename` filter matches nothing.
- **feat(tools):** `generate_basic_pdf` and `add_table` gain an optional `watermark` ({ text, fontSize?, opacity?, angle?, color? [r,g,b] 0–1, position? }). Omitted = byte-identical output. `opacity < 1.0` is rejected under `pdfA: 'pdfa1b'` (ISO 19005-1 §6.4 forbids transparency).
- **feat(tools):** `generate_basic_pdf` and `add_international_text` gain an optional `normalize` (`'NFC'|'NFD'|'NFKC'|'NFKD'`). `add_international_text` defaults to `'NFC'` (unchanged behaviour); `generate_basic_pdf` defaults to no normalization (byte-stable).
- **feat(tools):** `inspect_pdf`, `verify_pdf`, `validate_pdf`, `extract_text`, `extract_attachments` gain an optional `verbosity` input (`'summary'` | `'full'`, default `'full'`). `'summary'` returns a canonical scalar subset:
  - `inspect_pdf` → `{ version, pageCount, encryption, pdfA, signatureCount, hasSignaturePlaceholder, attachmentCount }`
  - `verify_pdf` → `{ signatureCount, allValid, invalid, summary }`
  - `validate_pdf` → `{ standard, valid, errorCount, warningCount, summary }`
  - `extract_text` → `{ pageCount, extractedPageCount, extractable, charCount }`
  - `extract_attachments` → `{ attachmentCount }`
- **feat(tools):** the read-only tools gain an optional `fields` input — a dot-path projection (e.g. `['allValid']`, `['signatures.valid']`) applied after `verbosity`. Unknown paths are omitted leniently. Backed by a new dependency-free `src/projection.ts` module.
- **feat(server):** `SERVER_INSTRUCTIONS` documents the new tool, watermark/normalize pitfalls, token-frugal reads, and base64 resource delivery.
- **docs:** new root `AGENTS.md` agent operations manual.

## Changed

- **chore(deps):** upgraded `zod` `^3.23.8` → `^4.0.0` (resolved 4.4.3). The MCP SDK peer range already permitted zod 4; the only source change was migrating one `superRefine` issue code to the zod-4 string-literal form.
- **chore(release):** `mcpName` (package.json) and `name` (server.json) → `io.github.Nizoka/pdfnative-mcp`; npm package name unchanged (`pdfnative-mcp`).
- **chore(release):** `SERVER_VERSION`, `server.json` versions, and `_meta.apiVersion` bumped `1.1.0` → `1.2.0` on every tool.
- **change(server):** base64-mode PDF-producing tools no longer duplicate the PDF into `structuredContent.base64`; the bytes are delivered once via the embedded `resource` content block. `base64` was an optional output field (never required), so this is not a breaking schema change. File mode (`{ mode, sizeBytes, filePath }`) is unchanged.
- **docs:** README, `AGENTS.md`, `docs/AI_GUIDE.md`, `docs/API_STABILITY.md`, `docs/KNOWLEDGE_BASE.md`, `ROADMAP.md`, and `llms.txt` updated for the v1.2.0 surface.

## Fixed

- **fix(registry):** MCP registry publication failed because validation compares `mcpName` to the GitHub namespace with case-sensitive equality (`Nizoka`), while the published metadata used lowercase `nizoka`. Corrected to `io.github.Nizoka/pdfnative-mcp`.

## Upgrade guide

1. Bump your dependency to `^1.2.0` — no code changes required; all v1.1.0 calls work unchanged and default responses are byte-identical.
2. **If you read PDF bytes from `structuredContent.base64`:** switch to the embedded `resource` content block (`content[].type === 'resource'`, `resource.blob` / `resource.uri`). `structuredContent` for base64 mode is now `{ mode, sizeBytes }`. File mode is unchanged.
3. **To save tokens on read-only tools:** add `verbosity: 'summary'` for a compact verdict, and/or `fields: [...]` to project to the exact paths you branch on. Smallest signed-and-valid probe: `{ pdfBase64, verbosity: 'summary', fields: ['allValid'] }`.
4. **To read attachments back:** call `extract_attachments` (the read-only counterpart to `add_attachment`).

## Compatibility

Backward-compatible minor release. Tool names, required inputs, error codes, and
default (`verbosity: 'full'`) response shapes are unchanged from v1.1.0. The only
behavioural change is the removal of the optional `base64` field from
`structuredContent` (the bytes remain available via the `resource` content block).
