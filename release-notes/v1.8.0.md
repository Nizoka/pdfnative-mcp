# pdfnative-mcp v1.8.0

<!-- GitHub Release title: v1.8.0 - Spot colours, right-to-left, JPEG 2000, 32 scripts, operator fonts, the release pipeline, pdfnative 1.9 -->

_Released 2026-10-31_

v1.8.0 aligns the server with [pdfnative v1.9.0](https://github.com/Nizoka/pdfnative)
and ports the release pipeline, the workflow lint and the coverage-guided fuzzing the
engine shipped with it. The catalogue stays at **28 tools**; what grows is what each of
them can do: **spot colours and ink mixes** anywhere a colour is accepted, a **base text
direction** (right-to-left documents laid out and extracted in reading order), the
**PDF/X-4 + PDF/A-2 dual claim**, **JPEG 2000** images, a **link annotation** on existing
documents, per-value **chart colours**, five more Indic scripts (**32 scripts**), four
more engine diagnostics (**13**), and three things only the operator can give an agent: a
**font sandbox** (`PDFNATIVE_MCP_FONT_DIR`), a **public URL** for every file-mode result
(`PDFNATIVE_MCP_OUTPUT_BASE_URL`, issue #66) and the **governance contract served as
resources**. Every item of the ROADMAP's *Next* section shipped.

No breaking changes to the tool API: every 1.7.0 input is still accepted, every tool,
property, enum value and bound is still there (the superset gate against the published
1.5.0 catalogue proves it), and default outputs are byte-identical except where
pdfnative 1.9.0 corrected previously-wrong output or where this release turned a silent
data loss into a coded error (both listed under *Upgrade*). All new behaviour is opt-in.

## Highlights

- **Spot colours** — `print.spotColours` declares inks with a CMYK or RGB alternate; `{ spot: 'Brand Blue', tint: 0.4 }` (`/Separation`) and `{ inks: { 'Brand Blue': 1, Varnish: 0.3 } }` (`/DeviceN`) are accepted at every one of the 46 colour sites of the catalogue. An undeclared ink is refused by name.
- **Right-to-left documents** — `direction: 'auto' | 'ltr' | 'rtl'` on the nine document tools and `inspect_layout`, overridable per paragraph; untagged output carries `/ActualText` on every right-to-left and reordered shaped run (`actualText`, default true), so `extract_text` returns the logical text for Arabic, Hebrew and the Indic, Thai, Khmer and Myanmar scripts without a PDF/A claim — ten extraction limits pinned at 1.7.0 are lifted.
- **One file, two claims** — `pdfx: 'pdfx4'` combines with `pdfA: 'pdfa2b' | 'pdfa2u'`; `pdfa1b` and `pdfa3b` are refused with the engine's own message. `validate_pdf { standard: 'pdf-x-4' }` now reads colour inside Form XObjects, images and Separation / DeviceN alternates, and its `caveats[]` say so.
- **JPEG 2000, links, chart colours** — `mimeType: 'image/jp2'` (a JP2 file or a raw codestream, passed through as `/JPXDecode`) on `embed_image`, the `image` block and `watermark.image`; `annotate_pdf { type: 'link', rect, url }` on an existing document; `series[].colors` (one colour per bar) and an optional series `label` on `add_chart`.
- **Operator knobs** — `PDFNATIVE_MCP_FONT_DIR` registers the operator's `.ttf` / `.otf` faces at boot, named by the `font` input (`FONT_NOT_FOUND` otherwise); `PDFNATIVE_MCP_OUTPUT_BASE_URL` makes every file-mode result carry a public `url` and name it instead of the host path; both refuse to start on an invalid value. Fourteen operator variables, all in `server.json`.
- **The pipeline of pdfnative 1.9.0** — `publish.yml` is five jobs (guard → build → publish → attest → registry): a tag-only refusal before any approval, one `npm pack` whose digests follow the bytes, a publish job that installs nothing and mints the only token, the registry's own bytes attested with three SBOMs and the Sigstore bundle attached to the release, then `server.json` published to the MCP registry with the workflow's OIDC identity. `workflow-lint` (zizmor + actionlint) is a required check, ClusterFuzzLite fuzzes five boundary targets, Node 26 runs the gate as an advisory job, every Linux job runs in egress block mode or audit mode with a dated reason.

## Added

### Engine 1.9.0 surface

- **feat(color):** spot colours and ink mixes. `print.spotColours[]` (`{ name, alternate: [c, m, y, k] | [r, g, b] }`, at most 32 inks) on the nine document tools; the shared colour module adds two `anyOf` members — `{ spot, tint? }` and `{ inks }` — to every colour property it serves (watermarks, header / footer templates, table cell borders, outline entries, chart `colors` and series `color`, the `link` and `svg` blocks), 46 sites in all. An ink painted without a declaration is `VALIDATION_ERROR` naming the ink; an empty or duplicate declaration is `PRINT_ERROR`; a tint outside 0–1 is `VALIDATION_ERROR` at the boundary. The member descriptions are deliberately terse: the long form is on `print.spotColours` and in `docs/guides/PRINT.md`.
- **feat(layout):** `direction` (`'auto'` reads each paragraph's first strong character and right-aligns right-to-left paragraphs; `'ltr'` / `'rtl'` force it) and `actualText` (default true; `false` restores the bare 1.7.0 glyph runs) on the nine document tools and on `inspect_layout`; `paragraph.direction` in `generate_basic_pdf` / `inspect_layout` overrides the document setting. Omitted, the bytes are those of 1.7.0.
- **feat(print):** the PDF/X-4 + PDF/A-2 dual claim: `pdfx: 'pdfx4'` with `pdfA: 'pdfa2b'` or `'pdfa2u'` writes both identifications in one file; `pdfa1b` (PDF 1.4 under a PDF 1.6 standard) and `pdfa3b` (embedded files, which PDF/X forbids) are refused before the build with the engine's two level-specific messages. `encrypt` stays exclusive.
- **feat(validate):** `validate_pdf { standard: 'pdf-x-4' }` inherits the engine's wider check — colour inside Form XObjects and images, Separation / DeviceN / Indexed alternates, type-4 tint transforms; the stale caveat "Not checked: colour inside Form XObjects and images" is gone and `caveats[]` now states what the 1.9.0 check covers. PDF/UA findings on table headers (`/TH` without `/Scope`, `/TD` without `/Headers`) come through unchanged.
- **feat(image):** `mimeType: 'image/jp2'` on `embed_image`, the `image` block of `generate_basic_pdf` / `inspect_layout` and `watermark.image`: a JP2 file (signature box `00 00 00 0C 6A 50 20 20`) or a raw JPEG 2000 codestream (`FF 4F FF 51`), magic bytes checked, passed through as `/JPXDecode` and never decoded. JPEG 2000 is PDF 1.5: under `pdfa1b` the engine raises `PDFA1_JPX_IMAGE`; an opacity channel or an unusual channel count raises `PDFA_JPX_IMAGE` under any PDF/A level.
- **feat(annotate):** `annotate_pdf` type `link` — `{ page, type: 'link', rect, url }` appends a `/Link` annotation with a `/URI` action to an existing page (the incremental-update twin of the `link` block); `url` is `http:`, `https:` or `mailto:` only, no control characters, refused at the boundary otherwise.
- **feat(chart):** `series[].colors` (one colour per value on `bar`, `barH`, `stackedBar`, `stackedBarH`; a length mismatch is `CHART_ERROR` with the engine's remedy) and an optional series `label` (an unlabelled series is listed as `Series N`).
- **feat(i18n):** `add_international_text.lang` gains `gu` (Gujarati), `pa` (Gurmukhi), `kn` (Kannada), `ml` (Malayalam) and `or` (Odia) on the engine's Indic shaper — 32 scripts. Every bundled shaper now reports its glyphs to the ToUnicode CMap, so the five claim PDF/A-2**u** under `strict` without a diagnostic and extract logically untagged.
- **feat(diagnostics):** four new engine codes, each with an executed trigger — `PDFA1_JPX_IMAGE`, `PDFA_JPX_IMAGE` (both escalate to `PDF_A_COMPLIANCE_VIOLATION` under `strict`), `PDFA_GLYPH_WITHOUT_UNICODE` (a level-U claim over a glyph no ToUnicode entry names — the engine reports the root cause `TEXT_GLYPH_NOT_COVERED` first, so `strict` stops there with `DIAGNOSTIC_ESCALATED`; `includeDiagnostics` lists both) and `TEXT_GLYPH_NOT_COVERED` (a character no registered font covers, drawn as a `.notdef` box or written as `?` — substitutions the server used to pass silently). Thirteen codes in all.
- **feat(extract):** `extract_text.onStreamError` — `'limit'` (default) fails a call whose content stream exceeds the decompression cap with `PDF_PARSE_FAILED` naming `PDFNATIVE_MCP_MAX_INFLATE_BYTES`, as `extract_attachments` and `inspect_pdf` already did; `'skip'` reads the rest of the document and the capped page comes back empty (the 1.7.0 behaviour, one opt-in away). The engine's `PdfStreamLimitError` is classified by its `code` (`PDF_STREAM_LIMIT`), never by its message, wherever it surfaces.
- **feat(ltv):** `add_ltv mode: 'offline'` composes `/DSS` + `/VRI` through the engine's `composeLtvData()` instead of its own glue; the new input `match` chooses `'all'` (default — every item referenced from every `/VRI`, the Adobe-tolerant superset) or `'chain'` (each `/VRI` references only what validates that signature; unmatched material still ships in `/DSS`). Default output unchanged.
- **feat(verify):** `verify_pdf` verifies ECDSA-SHA256 signatures through the engine's `ecdsaVerifyHash()`; the local P-256 reimplementation of 1.5.0–1.7.0 is deleted (SECURITY.md §Crypto scope updated).
- **feat(inspect):** `inspect_pdf` decodes the `/Info` text strings with the engine's `decodePdfTextString()` — a title written by `update_metadata` in any script reads back as the text, not as its UTF-16 bytes.
- **docs:** eight new executable examples (51 in total) — spot colours, right-to-left direction, the dual claim, JPEG 2000, link annotations, per-value chart colours, the five Indic scripts, the stream policy — rendered into the baseline through the built server; `examples/README.md` indexes them all.

### Operator knobs

- **feat(fonts):** `PDFNATIVE_MCP_FONT_DIR` — the operator font sandbox (ROADMAP *Next* since 1.7.0). An absolute directory of `.ttf` / `.otf` files (at most 64, 16 MiB each), each parsed by the engine's own font compiler (`parseFontData`, `pdfnative/tools`) and registered at boot under the slug of its file name (`Brand Sans.ttf` → `brand-sans`); a tool call names a face with the `font` input of `add_international_text`, `generate_basic_pdf` and `inspect_layout` (drawn first, the bundled faces as fallbacks; always embedded, so valid under PDF/A). An unknown slug is the new code **`FONT_NOT_FOUND`**, which lists the registered ones; a relative or missing directory, a file that is not a font, two files folding to one slug, too many or too large files refuse to start. The schema is static — the catalogue never varies by operator — and no tool argument ever carries a path.
- **feat(output):** `PDFNATIVE_MCP_OUTPUT_BASE_URL` (issue #66). When the operator serves `PDFNATIVE_MCP_OUTPUT_DIR` over HTTP, every file-mode result — single PDF, each part of `split_pdf`, the `draft_governance_issue` draft — carries `url` = base URL + sandbox-relative path (each segment percent-encoded), and the text block names that URL instead of the server's filesystem path; `filePath` stays in `structuredContent`. Pure string formatting: the server never requests that URL. An absolute `http:` / `https:` URL without credentials, query or fragment, normalised to a trailing slash; any other value, or a base URL without an output directory, refuses to start.
- **feat(governance):** two static resources, listed whether or not file output is enabled — `pdfnative://governance/policy` (`.github/ai-governance.json`, `application/json`) and `pdfnative://governance/rules` (`.github/AGENT_RULES.md`, `text/markdown`) — serve the AI-governance / human-in-the-loop contract byte for byte from `src/governance-embed.ts` (`npm run agents:governance` regenerates it; `verify:docs` rule `governance-embed` fails on drift), so an agent on a remote host reads the contract the repository holds. The policy names the test that covers its validator (`verification.validator_covered_by`).

### Repository hardening (aligned with pdfnative 1.9.0)

- **ci(publish):** the guard → build → publish → attest → registry pipeline. `guard` refuses anything but a `v*` tag equal to the package version before the environment prompt; `build` runs the publish gate with veraPDF (the composite action's new `home` output) and packs once, recording SHA-256 and SHA-512; `publish` (environment `npm-publish`, the only `id-token: write` on the npm path) installs nothing — the npm client is fetched and checked against a pinned SHA-512, the tarball is re-verified against the build digests and its inner version — and publishes with provenance; `attest` fetches the bytes the registry serves, checks them against the same digests, runs `npm audit signatures`, attests the tarball and three SBOMs (runtime CycloneDX and SPDX, build toolchain) and attaches them with the Sigstore bundle to the release; `registry` publishes `server.json` to the MCP registry through `mcp-publisher login github-oidc` with a publisher pinned by version, SHA-256 and `cosign verify-blob`. The attest job's `contents: write` is the pipeline's only write grant (accepted Scorecard finding, SECURITY.md).
- **ci:** `ci.yml` loses its `paths-ignore` (a required check must always report — a docs-only pull request stayed "Expected" forever) and gains `workflow-lint` (zizmor at medium severity, actionlint checked by SHA-256), a sixth required check in `.github/rulesets/main.json`; the Linux gate runs in `egress-policy: block` with an allow-list, as do `node-current`, `audit`, `dependency-review`, `docs` and `sample-regression`; the jobs still in audit mode carry a dated reason (`verapdf`, `scorecard`, `codeql`, `fuzz`, `workflow-lint`, the Windows gate). `codeql.yml` scans the `actions` language beside TypeScript with the `security-extended` suite and scopes `security-events: write` to its job. Event values reach `run:` scripts through `env:`, never through `${{ }}`. Dependabot waits seven days on every ecosystem and watches the fuzz engine and its image. `tests/tools/workflows.test.ts` asserts all of it.
- **ci(node-current):** `node-current.yml` runs the CI gate on Node 26 (LTS since 2026-10-28) on every push and pull request — advisory, never a required check, no `continue-on-error`.
- **ci(fuzz):** ClusterFuzzLite (`fuzz.yml`: five minutes on a pull request, thirty weekly) over five boundary targets in `fuzz/` — `tools/call` arguments through `callToolDirect` (a result must carry a documented code), the base64 decoders, the image decoder, the output sandbox (a path that resolves outside the sandbox is a bug) and the HTTP guards (a foreign Host or a wrong credential that passes is a bug) — seeded from the 51 examples by `tests/fuzzing/_fuzz-seeds.ts` and proved callable against `src/` on every gate run by `tests/fuzzing/targets.test.ts`. The Jazzer.js engine lives in `.clusterfuzzlite/engine` with its own exact manifest and lockfile, never in `package.json`; the build image is pinned by digest. The targets reach the server through `src/fuzz-surface.ts`, a named door onto internal functions, not part of the public API.
- **feat(gate):** a `pack-manifest` step (CI and publish profiles): the files `npm pack` ships are held to `tests/_fixtures/pack-manifest.json`, and two consecutive packs must be byte-identical.
- **test(matrix):** `tests/_fixtures/engine-surface.json` ties each of the 72 bullets of the engine's 1.9.0 changelog to named tests and samples (37) or to a written waiver (35). A new suite, `tests/engine-1-9.test.ts`, exercises the 1.9.0 surface option by option; `tests/client-compat.test.ts` holds every array bound of the catalogue to 1000 or the measured-good 5000 (issue #65).
- **test(conformance):** the veraPDF corpus grows from 41 to 45 files — JPEG 2000 under PDF/A-2b, spot colours and an ink mix under a CMYK OutputIntent, the PDF/X-4 + PDF/A-2b dual claim (checked by both validators), the five Indic scripts under PDF/A-2u — and `international-pdfa2u-taitham.pdf`, a negative canary since 1.7.0, is expected compliant (pdfnative 1.9.0 names every shaped glyph in `ToUnicode`; the XPASS was observed before the flip). veraPDF 1.30.2 on the release branch: 37 claiming files, 32 PASS, 5 expected failures (negative canaries), 0 unexpected; PDF/X-4 in-process: 7 files, 5 PASS, 2 expected failures. ## Upgrade

No breaking changes. Drop-in replacement for v1.7.0.

The repository's own sample baseline (`tests/_fixtures/samples.sha256.json`) was rebaselined once, before publication: of the 96 entries inherited from 1.7.0, 52 moved to `since: "1.8.0"` under pdfnative 1.9.0's byte ledger (C1–C28: every document embedding a font — lean, compact, tagged subsets —, every untagged document with right-to-left or reordered shaped text — `/ActualText` spans —, one text object per line, the danda routing, a font registered but never drawn) and 44 are byte-identical; 16 entries are new (the eight examples above and four corpus files: JPEG 2000, spot colours, the Indic scripts, the dual claim). The manifest's `provenance` note records the account; no entry was re-anchored for any other reason.

### Migrating from v1.7.0

1. **Rebaseline once if you compare bytes.** pdfnative 1.9.0 changes the bytes of every document that embeds a TrueType subset (lean, compact, renumbered into the document's CID space, six-letter subset tag — C6, C21, C28), of every untagged document with right-to-left or reordered shaped text (`/Span /ActualText` per run — C20, C27), of every document with a shaped run or a line that changes font (one text object per line — C25), of every Odia, Gurmukhi, Gujarati, Kannada or Malayalam line ending in a danda (C26) and of every document registering a font it never draws (C18, far smaller). Documents on base-14 fonts without those features are byte-identical. The engine's own release note has the ledger.
2. **`extract_text` fails on an over-cap stream.** A content stream over `PDFNATIVE_MCP_MAX_INFLATE_BYTES` yielded an empty page in 1.7.0 and now fails the call with `PDF_PARSE_FAILED` naming the variable — the behaviour the ROADMAP had asked for. A consumer that preferred the empty page passes `onStreamError: 'skip'`.
3. **`extract_text` returns logical order untagged.** Right-to-left and reordered shaped runs come back in reading order on untagged output too (they did only under a PDF/A claim). A consumer that post-processed visual order should stop; `actualText: false` on the generating call restores the bare runs.
4. **`verify_pdf` on the engine's ECDSA.** Same verdicts, one implementation; `EC_CURVE_UNSUPPORTED` and `VERIFY_FAILED` keep their triggers.
5. **One new error code.** `FONT_NOT_FOUND` can only be returned by a call that sets `font`. `PDF_PARSE_FAILED`, `VALIDATION_ERROR`, `PRINT_ERROR` and `CHART_ERROR` gained triggers (an over-cap stream; an undeclared spot ink, `pdfx` with `pdfa1b` / `pdfa3b`, a bad link `url`; a bad `print.spotColours` entry; a `colors` length mismatch) without changing their meaning. 48 codes in all.
6. **`strict` on an image.** A strict diagnostic raised by `embed_image` now carries its own code (`PDF_A_COMPLIANCE_VIOLATION`, …) instead of `VALIDATION_ERROR`.
7. **Protected documents are never cached.** A read with `password` is computed on every call (it was served from the opt-in cache); the first call is unchanged.
8. **The catalogue is larger.** `tools/list` is about 355 kB (306 kB in 1.7.0), under a budget raised to 384 KiB. A host that forwards every schema to the model on every turn pays the difference; the new members are terse and the long form lives in the guides.
9. **`TOOL_API_VERSION` is `1.8.0`.** `_meta.apiVersion` moves on every tool; the cache namespace with it.
10. **`resources/list` always lists two entries.** `pdfnative://governance/policy` and `pdfnative://governance/rules` come first, with or without `PDFNATIVE_MCP_OUTPUT_DIR`; a client that treated an empty list as "file output disabled" should test for `pdfnative://output/` entries instead. `resources/read` returns them as `text`, not `blob`.
11. **Operators:** `PDFNATIVE_MCP_FONT_DIR` and `PDFNATIVE_MCP_OUTPUT_BASE_URL` are honoured from this release; an invalid value — or a base URL without `PDFNATIVE_MCP_OUTPUT_DIR` — refuses to start. The `extract_text` default of item 2 can be reverted per call only.
12. **Hosts on `@modelcontextprotocol/server` semantics:** a 2026-07-28 request without the `MCP-Protocol-Version` header is now `400`; send the header (every conformant client does).

For maintainers of a fork: `publish.yml` is a different graph (the `npm-publish` environment now gates the `publish` job only; `attest` and `registry` need `id-token: write`; the MCP registry entry is published by the workflow — bind the `io.github.<owner>/*` namespace to the repository's OIDC identity before the first release); `main.json` requires `workflow-lint`; `npm run agents:governance` regenerates `src/governance-embed.ts`; the gate has a `pack-manifest` step.
